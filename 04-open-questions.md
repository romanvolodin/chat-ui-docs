# Веб-чат: отложенное и нерешённое

## Отложено сознательно

| Тема | Что решено |
| --- | --- |
| Роли и права в группах и каналах | Кто пишет, кто управляет участниками, кто удаляет чужие сообщения — отложено на будущее. |
| Доставка новых сообщений | Мгновенно или периодическим обновлением — вопрос отложен; этим должно заниматься само приложение. |
| Возможности ботов | Пока только отправка и получение сообщений, остальное потом. |
| Общая группа, связанная с каналом | Пока не нужна. |
| Баннер входящего сообщения в киноинтерфейсе | Можно реализовать позже. |
| Имитация набора текста собеседником | Можно реализовать позже. |
| Интерфейс для редактирования диалогов | Планируется в будущем, чтобы диалоги могли менять не только автор. |
| Интерфейс для изменения стилей и тем | Планируется в будущем для любого человека. |
| Экраны звонка, мини-окно, демонстрация экрана | Острой необходимости нет, для Киноинтерфейсов пригодятся. Сообщения о звонках в истории и кнопки звонка в шапке остаются в первой очереди. |
| Создание чатов, групп и каналов в интерфейсе | Пока не нужно. |
| Расширенные опросы | Пока только простые. Несколько ответов, публичные опросы, викторины и закрытые опросы позже. |
| Формат анимации Lottie для стикеров | Пока не поддерживаем, стикеры показываются как обычные изображения и видео. |
| Настоящая карта для геопозиции | Пока картинка-превью вместо карты, чтобы чат работал без интернета. |
| Режим «сейчас», при котором время идёт от заданной точки | Пока только замороженное «сейчас»; идущий режим можно добавить позже как отдельную настройку. |

## Будет обсуждаться отдельно

- Будущий бэкенд киноинтерфейсов, который будет имитировать Mirage JS.

## Решено «не нужно»

- Браузерные уведомления и звук нового сообщения.
- Мультиязычность интерфейса.
- Полная замена Telegram как цель.

## Пока не определено

| Тема | Состояние |
| --- | --- |
| Формат хранения диалогов для Киноинтерфейсов | Место хранения определено: для начала внутри движка чата (js-файлы и Mirage JS), позже появится полноценный бэкенд. Формат пока не определён. Автору удобно писать текст сообщений в Markdown, а в контракте интерфейса текст передаётся списком сегментов, поэтому преобразование Markdown в сегменты остаётся задачей движка чата. Нужно решить проблему ручного ведения id чатов и пользователей и сложного добавления чата. |
| Технический способ встраивания на страницу приложения | В обсуждении не фиксировался. |
| Контракт между интерфейсом и движком (какие данные интерфейс получает и какие события отдаёт) | Основные решения приняты и описаны в `06-contract.md`. Остаток (поля типов сообщений, окно информации, статусы, ссылки и др.) перечислен в разделе «Не решено» того документа. |
| Способ показа окна информации о чате | Боковая панель или модальное окно: решим позже. |
| Конфигурация и настройки киноинтерфейса на съёмке | Нужны настройки, относящиеся именно к работе киноинтерфейса; состав настроек не определён (известно только про переключение подстановки реплик и управление сценарием). |
| Возможность менять расположение элементов (например, время вне пузыря) | Хочется, но считается сложным. |
| Шестой экран звонка («отклонён» / «нет ответа») | Автор не уверен, что такие экраны бывают, но пусть будут. |

## Особенности текущего chat-app, которые нужно учесть при переносе

- Введённый пользователем текст не используется при отправке, реплика берётся из сценария. Нужна возможность отключить подстановку.
- Состояние хранится в Pinia-сторах.
- Диалоги и пользователи хранятся в js-файлах.
