## Цель

Спроектировать веб-чат, который может работать:

- как самостоятельное приложение;
- как компонент, встроенный в страницы других веб-приложений.

Результат работы — MD-документы.

## Что за чат

- Аналог Telegram: чаты между людьми, группы, каналы.
- Цели создать полноценную замену Telegram нет.

## Контекст

### Киноинтерфейсы

- Сервис, который предоставляет имитацию реальных интерфейсов на разных устройствах (ноутбуки, планшеты, телефоны) для съёмок фильмов и сериалов.
- Интерфейсы — статические сайты без бэкенда.
- Чат — один из важных интерфейсов: когда актёр пишет в чат, скрипт имитирует ответ собеседника.
- Чат должен работать без интернета на съёмочной площадке.

### Паприка

- В Паприке тоже есть чаты.
- В Паприке используются Vue.js и Pinia.
- В Паприке будет бэкенд (поиск, выдача истории и доставка сообщений реализуются на стороне приложения).

### Первоочередная цель

В первую очередь нужен чат для Киноинтерфейсов. Наработки при этом нужно использовать и в Паприке, чтобы не дублировать работу. Обновления чата должны делаться в одном месте.

## Режимы использования

1. **Самостоятельное приложение.** Есть движок чата, который хранит состояние и манипулирует данными.
2. **Встроенный чат.** Данные создаёт, получает и меняет само приложение, в которое чат встроен, и передаёт их чату.

Чат может использоваться несколько раз, в том числе внутри одного проекта. Например, в Киноинтерфейсах это может быть самостоятельный мессенджер вроде Telegram и чат внутри социальной сети. Стили при этом должны различаться. То же относится к Паприке.

## Пользователи

Поддерживаются оба варианта:

- собственная регистрация и учётные записи чата;
- пользователи из приложений, в которые чат встроен (с их авторизацией).

## Как выглядит встраивание

Встраивается чат целиком, но на странице приложения показывается конкретный диалог с переходом к списку чатов.

Пример — Yougile:

- к каждой задаче привязан чат;
- при входе в задачу открывается переписка по этой задаче;
- по кнопке в шапке страницы можно перейти к списку чатов, где видно, в каких задачах есть непрочитанные сообщения.

Привязанные чаты (например, чат задачи) создаёт приложение, в которое встроен чат.

Чат должен подстраиваться под размеры произвольного блока.

## Текущее состояние чата для Киноинтерфейсов

Репозиторий: <https://github.com/romanvolodin/chat-app>

По коду репозитория:

- Стек: Vue 3, Pinia, Vue Router, VueUse, сборка через Vite, подключён PWA-плагин.
- Интерфейс: список чатов, шапка чата, область сообщений, поле ввода. Типы сообщений: текст, эмодзи, видеокружок. Есть цитаты, реакции, группировка сообщений по автору.
- Адаптивность: на ширине до 600 px показывается либо список чатов, либо диалог.
- Данные: каждый чат — js-файл в `data/chats/`, все они импортируются в `chatsAll.js`. У чата есть поля `id`, `name`, `avatar`, `onlineStatus`, `users`, `currentUser`, `unread`, `isMuted`, `history` (уже показанные сообщения) и `dialog` (сценарий). Пользователи лежат отдельно в `users.js`, сообщения ссылаются на них объектами.
- Имитация ответа: при отправке сообщения из `dialog` показывается следующая реплика. Если следующая реплика не от `currentUser`, она появляется автоматически через заданный `delay`. Текст, который ввёл пользователь, обработчик отправки не использует.
- Отсутствуют (судя по списку компонентов): отличия групп от каналов, стикеры, опросы, файлы, аудио, пересылка, редактирование, удаление.

### Проблемы текущей реализации

- Диалоги хранятся в js-файлах, это неудобно.
- Сложно следить за id чатов и пользователей.
- Чтобы добавить чат, нужно много ручных действий, из-за этого случаются ошибки.
- Диалоги сейчас создаёт и редактирует только автор, потому что для этого нужно лезть в исходный код. В будущем планируется удобный интерфейс, чтобы менять диалоги могли и другие люди.

## Принципы

- Язык интерфейса — русский, мультиязычность не нужна.
- Интерфейс адаптивный, работает на всех устройствах.
