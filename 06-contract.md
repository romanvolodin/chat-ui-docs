# Веб-чат: контракт ChatRoot (черновик)

Документ описывает, что чат целиком (`ChatRoot`) получает снаружи и что сообщает наружу. «Снаружи» это движок чата. У каждого приложения свой движок чата (в Киноинтерфейсах и в Паприке они разные). Источники: `01`–`05` и решения, принятые в обсуждении контракта.

## Границы документа

- Контракт описан только на уровне `ChatRoot`. Props и события внутренних компонентов не описываются.
- Контракт состоит из данных и событий. Настройки (раздел 4) обсуждаются отдельно.
- Имена полей и событий в коде в этом черновике не фиксируются, поля описаны по смыслу.
- В колонке «Основание» указано, откуда взято утверждение:
  - **решено** — принято в обсуждении контракта;
  - **требования** — следует из `02-requirements.md`;
  - **вывод** — мой вывод из принятых решений, нужна проверка.

## 1. Принципы

| № | Принцип | Основание |
| --- | --- | --- |
| 1 | Данные идут в интерфейс, действия пользователя идут наружу событиями. Интерфейс показывает столько данных, сколько выдали, и ничего не выполняет сам. | решено (`03`, п. 2) |
| 2 | Какой чат сейчас открыт, хранит движок чата. Интерфейс о выборе пользователя только сообщает. | решено |
| 3 | Пользователи передаются по id и отдельным справочником. В сообщениях, цитатах и реакциях стоят только id. Движок чата, отдавая сообщения, отдаёт и справочник на их авторов. | решено |
| 4 | Автор любого сообщения это запись справочника (имя и аватар). Интерфейс не различает человека, канал, бота или администратора. Для постов канала в справочник добавляется запись канала. | решено |
| 5 | Если пользователя из сообщения нет в справочнике, интерфейс показывает заглушку («Неизвестный пользователь», пустой аватар). Другое имя или аватар задаёт движок чата, добавив запись в справочник. | решено |
| 6 | Все длинные списки подгружаются по одному принципу: интерфейс показывает, сколько выдали, и сообщает наружу, когда пользователь докрутил до конца. Размер порции произвольный. | решено |
| 7 | Время приходит как момент времени (дата и время). Интерфейс сам форматирует его и считает «сегодня» и «вчера». | решено |
| 8 | Текущий пользователь («я») один на весь экземпляр чата. Для разных «я» используются разные экземпляры. | решено |
| 9 | Элементы управления для съёмки (подстановка реплик, управление сценарием, «нет сети» и ошибка отправки по команде оператора) рисует движок чата. В пакете интерфейса их нет. | решено |
| 10 | Для интерфейса все чаты обычные. «Избранное», чат поста канала и чат закреплённых сообщений создаёт движок чата: он заполняет название, аватар, нижнюю панель и историю. Особых режимов в интерфейсе нет. | решено |
| 11 | Что показывать вместо поля ввода, указывает одно поле данных чата («нижняя панель»). Интерфейс не решает это по типу чата или признаку подписки. | решено |
| 12 | Подпись под названием чата: пока необязательное поле не заполнено, интерфейс собирает статусную строку из данных (присутствие, число участников, «печатает…»). Если поле заполнено, показывается оно. | решено |
| 13 | Форматирование текста передаётся списком сегментов, а не разметкой и не диапазонами с позициями. Сегмент это кусок текста и необязательный список видов форматирования. Так же передаются подписи к вложениям и черновик. Предпросмотр форматирования показывается прямо в поле ввода. | решено |

## 2. Данные: что ChatRoot получает

### 2.1 Общие данные экземпляра

| Что | Описание | Основание |
| --- | --- | --- |
| Текущий пользователь | Id пользователя, от имени которого работает чат | решено |
| Справочник пользователей | Записи пользователей: имя, аватар, необязательный телефон (нужен для сообщения-контакта). Для личного чата и статусов нужны ещё статус присутствия («онлайн», «был в сети») и пометка «Бот» | решено (имя, аватар); требования (статус, пометка) |
| Открытый чат | Id открытого чата. Хранится снаружи | решено |
| Основной список чатов | Чаты в готовом порядке (закреплённые вверху). Порядок задаёт движок чата, интерфейс не сортирует | решено |
| Архив | Отдельный готовый список чатов | решено |

### 2.2 Чат

| Что | Описание | Основание |
| --- | --- | --- |
| Id и тип | Тип: личный, группа, канал, чат поста канала. «Избранное» и чат закреплённых сообщений для интерфейса обычные чаты | решено (принцип 10); требования (типы) |
| Название и аватар | Всегда заполнены, в том числе у личного чата. Для личного чата их подставляет движок чата | решено |
| Подпись под названием | Необязательное поле. Если заполнено, показывается вместо статусной строки (например, «Сохранённые сообщения», «{количество} комментариев») | решено |
| Собеседник | У личного чата сохраняется id собеседника. По нему берутся статус, «печатает…», пометка «Бот», блокировка | решено |
| Нижняя панель | Одно поле с вариантом: поле ввода, кнопка звука, «Присоединиться», «Открепить все сообщения», заглушка «только чтение». Значение указывает движок чата | решено |
| Звук отключён | Признак для значка в списке и для надписи кнопки «Включить звук» / «Отключить звук» | решено |
| Закреплён | Признак для значка в списке. Для сортировки и фильтрации не используется | решено |
| Фон | Адрес картинки фона чата. Если не задан, фон берётся из темы | решено |
| Черновик | Сохранённый текст черновика. Интерфейс сам его не хранит | решено |
| Последнее сообщение | Краткое содержимое последнего сообщения для строки списка (автор, текст или тип, время, статус) | вывод |
| Счётчики непрочитанных | Число непрочитанных сообщений и непрочитанных упоминаний | требования |
| Число участников | Для статусной строки группы и канала | требования |
| Кто печатает | Список пользователей, которые печатают сейчас | требования |
| Закреплённые сообщения | Несколько. Полоса переключается между ними. Каждое закреплённое сообщение приходит готовым фрагментом (как цитата), потому что оно может быть вне загруженной истории | решено (несколько, переключение); вывод (фрагменты) |
| Первое непрочитанное | Положение первого непрочитанного сообщения | требования |

### 2.3 Сообщение

| Что | Описание | Основание |
| --- | --- | --- |
| Id, время, автор | Автор это id из справочника | решено |
| Тип и содержимое | Текст, картинки, видео, файлы, аудио, видеокружки, стикеры, опросы, подписи, альбомы, GIF, геопозиция, контакт, звонок. Поля каждого типа в подразделе «Содержимое по типам» | требования |
| Статус | «Отправляется», «отправлено», «прочитано», «ошибка» | решено (отправляется, отправлено, ошибка); требования (прочитано) |
| Пометки | «Изменено», «Переслано от…» (автор записью справочника) | требования |
| Закреплено | Признак для иконки булавки в подвале пузыря, слева от времени | вывод |
| Просмотры | Необязательное число. Если задано, в подвале пузыря показываются иконка и счётчик просмотров (у постов канала) | вывод |
| Комментарии | Необязательное число. Не задано: кнопки нет. Ноль: «Прокомментировать». N: «N комментариев». Вид кнопки (полоса под пузырём или иконка у видеокружка) интерфейс выбирает по типу сообщения | решено |
| Ответ (цитата) | Id исходного сообщения и готовый фрагмент: автор, текст или тип вложения. Для ответа на выделенные слова в цитате именно эти слова | решено |
| Реакции | Для каждой: значок, счётчик, признак «моя реакция». Список поставивших в сообщении не лежит | решено |
| Системное сообщение | Отдельный вид сообщения («Иван добавлен в группу», «Начало обсуждения») | требования, решено (для чата поста) |

Чат поста канала: пост приходит обычным первым сообщением истории, затем системное сообщение «Начало обсуждения», затем сообщения пользователей. Отдельного блока «исходный пост» нет. В шапке такого чата «{количество} комментариев» и иконка канала: это название и аватар чата.

Чат закреплённых сообщений: история состоит из закреплённых сообщений исходного чата. Id сообщений совпадают с исходными, иначе переход к сообщению не найдёт нужное.

#### Содержимое по типам

| Тип | Что приходит | Основание |
| --- | --- | --- |
| Текст | Список сегментов. Сегмент это кусок текста и необязательный список видов форматирования (жирный, курсив, код, ссылка, упоминание). У ссылки хранится адрес отдельно от видимого текста, у упоминания id пользователя из справочника. Склеенные подряд сегменты дают исходный текст. Подпись к вложению устроена так же | решено (форма); вывод (список видов) |
| Картинка | Адрес файла, ширина и высота. Необязательно адрес миниатюры: если его нет, показывается сам файл | решено |
| Видео | Поля как у картинки и длительность. Миниатюра служит обложкой | решено (поля); вывод (длительность) |
| Альбом | Список картинок и видео вместе в одном сообщении. Подпись одна на альбом | решено (смешанный состав); вывод (общая подпись) |
| Файл | Имя, размер, значок типа и адрес. По нажатию интерфейс скачивает или открывает файл сам, наружу ничего не сообщается | решено |
| Аудиосообщение | Адрес файла, длительность и список значений громкости для «волны». Без списка показывается полоса прогресса. Выбор скорости воспроизведения | решено; требования (скорость) |
| Видеокружок | Адрес файла (и длительность). Обложки нет. В чате маленький, играет в цикле без звука. По нажатию увеличивается и играет сначала со звуком. После завершения возвращается в маленькое состояние без звука | решено (поведение); вывод (длительность) |
| Стикер, GIF, анимированное эмодзи | Показываются как обычные изображения и видео (png, webp, gif, webm, mp4): адрес и размеры. Формата Lottie нет | решено; вывод (размеры) |
| Опрос | Вопрос и варианты ответов. Для каждого варианта число голосов и признак «мой выбор». Один выбор, голосование анонимное. Расширенные виды позже | решено |
| Геопозиция | Координаты, подпись и адрес картинки-превью вместо карты. Нажатие на сообщение сообщается наружу | решено |
| Контакт | Id пользователя из справочника. Имя и аватар берутся оттуда, телефон тоже | решено |
| Звонок | Что показывается в сообщении и как длительность: не решено | требования |

Пример текста с форматированием (имена полей условные, в контракте они не фиксируются):

```json
"text": [
  { "text": "Привет, " },
  { "text": "@Яна", "format": ["mention"], "user": "user128402699" },
  { "text": ", вот " },
  { "text": "1 серия", "format": ["bold", "italic"] },
  { "text": ": " },
  { "text": "презентация", "format": ["link"], "url": "https://example.com/keynote" },
  { "text": ".\nФайл " },
  { "text": "ep01_v3.mov", "format": ["code"] }
]
```

### 2.4 История сообщений открытого чата

| Что | Описание | Основание |
| --- | --- | --- |
| Загруженная часть истории | Упорядоченный список сообщений. Может быть любой частью истории, не только концом | решено |
| Переход к далёкому сообщению | При переходе к сообщению, которого нет в списке (из цитаты, закрепа, поиска, ссылки), снаружи заменяют загруженную часть на окно вокруг него. Интерфейс подсвечивает это сообщение | решено |
| Подгрузка | В обе стороны: по сообщению «докрутил до верха» и «докрутил до низа» снаружи выдают следующую порцию | решено |

### 2.5 Результаты поиска и вторичные списки

| Что | Описание | Основание |
| --- | --- | --- |
| Результаты общего поиска | Сообщения, пользователи, чаты. Привязаны к запросу, на который выданы; устаревшие интерфейс игнорирует | решено (по мере ввода); вывод (привязка) |
| Результаты поиска внутри чата | Найденные сообщения с возможностью перехода между ними | требования |
| Кто поставил реакцию | Выдаётся по запросу как обычный длинный список | решено |
| Окно информации о чате | Участники, медиа, файлы, ссылки. Каждый список подгружается порциями | решено (принцип подгрузки); требования (состав) |

## 3. События: что ChatRoot сообщает наружу

### 3.1 Решено

| Событие | Что передаётся | Когда |
| --- | --- | --- |
| Выбран чат | Id чата | Пользователь нажал на чат в списке |
| Дочитано до сообщения | Id сообщения | Пользователь увидел сообщения до этого включительно (одно значение вида «прочитано до X») |
| Докручено до верха | Для списка чатов, истории и других списков | Пользователь докрутил список до начала |
| Докручено до низа | Для истории и других списков | Пользователь докрутил до конца |
| Перейти к сообщению | Id сообщения | Нажатие на цитату, закреплённое сообщение, результат поиска, открытие ссылки |
| Перейти к последним сообщениям | — | Нажатие на кнопку «вниз», если свежих сообщений нет в загруженной части |
| Изменён текст в поле ввода | Текст черновика в виде сегментов | Любое изменение (можно объединять с небольшой задержкой) |
| Отправить сообщение | Содержимое сообщения: текст в виде сегментов, вложения | Нажатие «отправить» |
| Переслать сообщения | Id сообщений и id чата-получателя | Выбор чата в окне пересылки |
| Поисковый запрос | Запрос и область поиска (общий или внутри чата) | По мере ввода с небольшой задержкой, по Enter немедленно |
| Показать, кто поставил реакцию | Id сообщения и реакция | Нажатие на реакцию |
| Нажатие на автора | Id автора из справочника | Нажатие на имя или аватар автора |
| Нажатие на кнопку звонка | Тип звонка (аудио или видео) | Нажатие кнопки в шапке |
| Нажатие на геопозицию | Id сообщения | Нажатие на сообщение с геопозицией |
| Включить или отключить звук канала | Id канала | Нажатие кнопки вместо поля ввода |
| Присоединиться | Id чата | Нажатие кнопки «Присоединиться» |
| Открыть закреплённые | Id чата | Нажатие кнопки в полосе закреплённых сообщений. Чат закреплённых открывают снаружи |
| Открепить все сообщения | Id чата | Нажатие кнопки в чате закреплённых сообщений |

### 3.2 Из требований, детали не обсуждались

Остальные действия из `02-requirements.md` тоже сообщаются событиями. Состав передаваемых данных нужно обсудить:

- ответить (в том числе на выделенный фрагмент), отредактировать, удалить (у себя и у всех);
- поставить или снять реакцию;
- закрепить и открепить сообщение;
- получить ссылку на сообщение или чат;
- проголосовать в простом опросе (id опроса и выбранный вариант);
- повторить отправку после ошибки;
- закрепить чат, отправить чат в архив, отключить звук чата;
- заблокировать пользователя;
- открыть чат комментариев к сообщению (кнопка «Прокомментировать» или «N комментариев»).

## 4. Настройки (обсуждаются отдельно)

Уже решено:

| Настройка | Описание | Основание |
| --- | --- | --- |
| Часовой пояс | Задаёт движок чата. По умолчанию пояс устройства | решено |
| «Сейчас» | Необязательный момент (дата и время) для Киноинтерфейсов и Storybook. Замороженный: не идёт, пока снаружи не передадут новое. Если не задан, используются реальные часы | решено |

Из требований, не обсуждались: режим «только чтение» для встроенного чата, контекст открытия, тема оформления, изоляция стилей.

## 5. Не решено

- Загрузка файлов при отправке: какие данные нужны для прогресса и отмены.
- Полный список видов форматирования (в контракте пока: жирный, курсив, код, ссылка, упоминание).
- Допускается ли вместо списка сегментов простая строка для текста без форматирования.
- Выбор скорости воспроизведения аудио и видеокружка: как передаётся и хранится.
- Как передаётся ответ на выделенные слова: что именно хранится (только слова или ещё и позиция в исходном сообщении).
- Полный список значений поля «нижняя панель» и данные, которые нужны каждому значению.
- Данные окна информации о чате: каждая вкладка списка и блокировка.
- Статусы «онлайн» и «был в сети», «печатает…»: как обновляются.
- Откуда берутся состояния «загрузка» и «нет соединения».
- Ссылки на чат и сообщение: кто формирует и разбирает адрес.
- Привязка результатов поиска к запросу: подробности формата.
- Управление с клавиатуры.
